## Текущее состояние: перенос подтверждённого пути Zorava в Волну

### Повторный запрос разблокировки и выбор старого действия

После чистой установки пользователь сообщил: звонок на разблокированном устройстве работает, на заблокированном Siri просит разблокировать. Это подтверждает работу SiriKit/Realtime, но не фонового запуска.

Значит, как минимум эта попытка выбрала сохранённый foreground-путь, а не расширение SiriKit. Настройки блокировки и entitlements обеих SiriKit-интеграций сопоставлены с Zorava: соответствующие ограничения пусты, Siri entitlement есть.

Из версии 3 удалён сам `CallGPTIntent`, который ранее оставлялся для совместимости, а не только AppShortcutsProvider. Чистая сборка версии 3 прошла: файлов actionsdata нет, строка CallGPTIntent отсутствует в исполняемом файле. В 22:23 устройство подтвердило установленную версию 3; приложение запущено. Требуется повторить физический сценарий. Пользователь подтвердил удаление старой сохранённой команды. Старые пользовательские workflows могут продолжать существовать независимо от удаления действия из приложения.

В диагностической Zorava пользователь подтвердил сигналы без разблокировки. Логи показали получение `INStartCallIntent`, принятие CallKit-транзакции и активацию аудио при `state=2`, `protectedData=false`. Подробности: [TONE-TEST.md](../archive/speakerbox/TONE-TEST.md).

В Волну перенесён тот же системный путь: SiriKit extension разрешает единственного AI-адресата, возвращает `continueInApp`, UIKit AppDelegate/SceneDelegate принимает activity при холодном и тёплом запуске и сразу запрашивает CallKit. Realtime/WebRTC использует аудиосессию, активированную CallKit. Ожидание активного приложения оставлено для входящей ссылки. AppShortcutsProvider и CallGPTIntent убраны, чтобы foreground-действие не конкурировало с системным звонком.

Фразы для проверки: **Call Volna using Volna** / **Позвони Волне через Волну**. Адресат и словарь общие для приложения и расширения; настоящий контакт в адресной книге не требуется. Сначала нужно выдать разрешения Siri и микрофона в настройках Волны.

Сборка для устройства и три существующих UI-теста прошли. При обновлении поверх старого SwiftUI-приложения iPhone восстанавливал `SwiftUI.AppSceneDelegate` из `Library/Saved Application State`, обходя новый делегат. После удаления пользователем и чистой установки 21.09.2026 в 22:11 подтверждены `scene.configuration` и `scene.connect`; HTTPS-настройки восстановлены, ядро готово. Для распространения обновления существующим пользователям потребуется отдельная миграция сохранённых сцен.

**Ожидается проверка полноценного Realtime-разговора через Siri на заблокированном iPhone.** Успех Zorava не считается подтверждением этого сценария в Волне. DEBUG-диагностика `volnaLaunchStages` содержит до 80 этапов без речи, токенов и контактов; маркер `volna-sirikit-1`.

## Подтверждённый сбой

На iPhone 15 Pro Max с iOS 27 действие Call Volna из Shortcuts возвращало `unknown error`. Диагностическая сборка зафиксировала:

1. `perform()` App Intent вызван в процессе приложения.
2. Разрешение микрофона получено.
3. Настройка аудиосессии прошла.
4. `CXCallController.request` отклонён: `com.apple.CallKit.error.requesttransaction`, код 6 (`invalidAction`).
5. Создание Realtime-сессии не началось.

Таким образом, этот воспроизведённый сбой происходит после распознавания действия и до обращения к OpenAI. Сам по себе код 6 не доказывает причину отказа.

## Проверяемое изменение

Один `openAppWhenRun = true` ошибку не устранил. Следующий замер показал: при запуске из Shortcuts `UIApplication.applicationState == .inactive` и CallKit возвращает 6; при запуске кнопкой состояние `.active` и CallKit принимает транзакцию.

Исправление: App Intent ставит запрос звонка в очередь и завершает передачу управления. Приложение запускает CallKit после `UIApplication.didBecomeActiveNotification`; если оно уже активно, запрос обрабатывается сразу. Этот вариант выводит приложение на экран и может требовать разблокировку iPhone.

Отдельно в установленной копии отсутствовал сохранённый HTTPS-адрес: использовался localhost по умолчанию. Адрес и токен восстановлены по USB; пользователь подтвердил звонок кнопкой, в диагностике получено `realtime.ready`. Потеря настройки не объясняет более ранний отказ CallKit.

## Актуальная документация Apple

- [Apple Intelligence and Siri AI](https://developer.apple.com/documentation/appintents/apple-intelligence-and-siri-ai): схемы описывают системе семантику действий; наличие приложения и наличие доступного действия — разные вещи.
- [phone.startCall](https://developer.apple.com/documentation/appintents/appschema/phoneintent/startcall): новая схема начала звонка, доступная с iOS 27. В установленном SDK Xcode 26.5 её нет. Отсутствие схемы не объясняет само по себе подтверждённый отказ CallKit при ручном запуске Shortcuts.
- [AudioRecordingIntent](https://developer.apple.com/documentation/appintents/audiorecordingintent): для записи требуется активная Live Activity. Нельзя просто добавить протокол и считать фоновое аудио настроенным.
- [App Intent runtime](https://developer.apple.com/documentation/appintents/getting-started-with-the-app-intents-framework): режимы исполнения задаются через `supportedModes`; прежний `openAppWhenRun` поддерживает старые версии iOS.
- [CallKit invalidAction](https://developer.apple.com/documentation/callkit/cxerrorcoderequesttransactionerror-swift.struct/code/invalidaction): значение ошибки не раскрывает, какое именно условие выполнения нарушено.

## Проверка исправления

Регрессионная проверка должна вызывать реальное действие из Shortcuts на физическом телефоне. Прямой вызов `perform()` в unit-тесте не воспроизводит системный контекст запуска и даёт ложную уверенность. Проверки ядра или успешная сборка не заменяют этот сценарий.

После исправления пользователь сначала подтвердил запуск из Shortcuts, затем подтвердил голосовой запуск через Siri («ооо работает»). Временные диагностические записи из кода удалены. Тот же порядок передачи управления применяется к SiriKit и входящей ссылке; отложенный запрос старше 15 секунд отменяется, чтобы случайное последующее открытие приложения не начинало звонок.

## Отдельная интеграция Siri AI

[WWDC26: Build intelligent Siri experiences with App Schemas](https://developer.apple.com/videos/play/wwdc2026/240/), раздел Making actions available: Apple отдельно объясняет, что обычные App Intents доступны в Shortcuts, а схемы позволяют новой Siri понимать и исполнять действия. Текущая реализация содержит App Shortcut без схемы звонка. Схема `phone.startCall` с описанием адресата и типа звонка — возможное направление полноценной семантической интеграции под SDK iOS 27. Однако текущий голосовой запуск через App Shortcut уже подтверждён пользователем без этой схемы. Утверждать, что для данного сценария обязательно обновление Xcode, было бы неверно. Подтверждённое исправление — порядок активации приложения перед CallKit; результат проверки с заблокированного экрана приведён ниже.

## Проверка заблокированного экрана

Пользователь подтвердил: действующий App Shortcut не запускается без открытия приложения с заблокированного экрана. Его foreground-режим сохранён, поскольку он устраняет воспроизведённую ошибку CallKit.

Для отдельной проверки системного SiriKit-звонка обработчик `INStartCallIntent` теперь начинает звонок при получении системной activity, не ожидая активной сцены. В резолвере единственного AI-адресата добавлены названия assistant / ассистент / помощник. Тестовая фраза «Call assistant using Volna» отличается от зарегистрированных App Shortcut-фраз. Пользователь проверил: Siri снова требует разблокировку. Экспериментальный прямой запуск возвращён к очереди до активации, чтобы не оставлять риск прежнего CallKit error 6. Запуск без разблокировки на этом устройстве не достигнут.

Apple указывает для [INStartCallIntent](https://developer.apple.com/documentation/intents/instartcallintent), что разблокировка требуется не всегда. Это не гарантия во всех состояниях телефона: [ответ Apple DTS](https://developer.apple.com/forums/thread/799337) отдельно обсуждает влияние системной политики Siri и положения устройства. Обычный фоновый App Intent и системный intent звонка — разные пути запуска.
