## 1. Паспорт инструмента

Всё, что нужно маршрутизатору, живёт в `defineTool`, а не в отдельных списках; `defineTool` проверяет паспорт:

| Поле | Значения | Зачем |
|---|---|---|
| `pack` | `call` (всегда), `time`, `self`, `memory`, `planner`, `contacts`, `code`, `web`, `work` (`assistant/tools/packs.ts`; с 23.09.2026, см. «Два вида работы» в конце) | набор, из которого Jev выбирает первым |
| `effect` | `read`, `write`, `act` | `act` (необратимое) только после кнопки на телефоне ([design/volna-confirm.html](design/volna-confirm.html)) |
| `latency` | `instant`, `fast`, `long` | ещё нет, появится с фоновыми заданиями (шаг 4): `long` не ждёт в разговоре |
| `jev` | `{ when, args }` или нет | карточка для Jev; без неё инструмент не попадает в быстрый путь |

Кандидаты Jev собираются из реестра. Новый инструмент добавляется одним файлом, как сейчас.

## 2. Маршрутизатор: один запрос к Jev, три этажа

Jev отвечает на несколько вопросов за один запрос (~0,4 с), поэтому вся развилка решается за один проход:

- `tool`: какой инструмент с карточкой отвечает сразу (плюс `none`), и вопросы-выборы для его аргументов;
- `pack`: какой набор нужен (плюс `none`: без инструментов, `mixed`: несколько или неясно);
- `tier`: класс задачи (раздел 3).

Этажи:

1. **Мгновенно.** Уверенный `read`-инструмент с карточкой: ядро исполняет его и отвечает без LLM (как быстрый путь сейчас).
2. **Быстро.** LLM из таблицы маршрутов получает только инструменты выбранного набора и служебный `escalate` (набор угадан неверно → повтор со всеми инструментами и классом выше).
3. **Долго.** Задание с id, статусом и отменой голосом. Волна говорит «запустила, скажу, когда будет»; результат приходит в идущий звонок через `LiveCalls.announce`, после звонка пушем. Код идёт в Claude Code через Пульт (`agents_start`).

При неуверенном `pack` LLM получает все инструменты, как сейчас.

## 3. Таблица маршрутов

Конфиг `.env` (`CLIENT_MODEL_SIMPLE`, `CLIENT_MODEL_STANDARD`, `CLIENT_MODEL_DEEP`), не код. Все модели идут через `chatModel` (OpenRouter), меняется только строка модели.

| `tier` | Исполнитель | Примеры |
|---|---|---|
| `instant` | без LLM | время, агенты, «кто ты» |
| `simple` | Gemini 3.5 Flash Lite (Haiku 4.5 одной строкой `CLIENT_MODEL_SIMPLE`) | напоминание, событие, контакт |
| `standard` | Sonnet 5 | поиск со сводкой, несколько шагов, память |
| `deep` | Opus 5.5; пока в разговоре, фоновым заданием станет на шаге 4 | план, разбор, «подумай над…» |
| `code` | Claude Code через Пульт | задачи в проектах |
| `computer` | Астра (Codex) через Пульт, фоновым заданием (`computer_start`) | управление приложениями Mac |

- `simple` по умолчанию не Haiku: бенчмарк 22.09.2026 ([core.md, 4h](core.md#4h-клиентское-делегирование)) дал ход 0,6 с у Gemini против 2,2 с у Haiku при одинаковой честности.
- Эскалация: `escalate`, ошибка или исчерпанные круги повторяют задачу классом выше.
- Неуверенный `tier` (ниже порога) даёт `standard`, а не `simple`.
- Замеры: маршрут, класс, задержка, круги, эскалации, токены. `npm run metrics` показывает их по маршрутам.
- Бюджет на задание для `deep` (и позже `computer`): лимит кругов и токенов.

### 3.1. Что говорит сообщество (22.09.2026)

Сводка обсуждений (Hacker News, Reddit) и замеров вендоров. Справка для выбора строки модели, а не решение: таблица выше не меняется без владельца. Общий тон: флагманы почти сравнялись, выбор зависит от формы задачи.

| Задача | Чаще выбирают | Основание |
|---|---|---|
| Текст, сводки, пересказ голосом | Claude | самое устойчивое согласие: меньше шаблонности |
| Точное следование инструкциям, быстрый класс | Haiku 4.5 | стабильная задержка первого токена, держит несколько ограничений; альтернатива GPT-4.1 / GPT-5 mini |
| Работа в большом репозитории, рефакторинг, интерфейс | Claude (Opus) | SWE-bench Pro 79,2 против 64,6 у GPT-5.6 Sol; UI при широкой постановке |
| Новые задачи без прецедента, управление GUI | Opus 5 | ARC-AGI-3, OSWorld 2.0 |
| Долгие автономные прогоны «запустил и ушёл», терминал | GPT / Codex | песочница без запросов разрешений; Terminal-Bench, DeepSWE немного выше |
| Ревью кода, проверка фактов | GPT / Codex | прямее возражает; частая практика: одна модель проверяет другую |
| Веб-исследование, картинки, интеграции | GPT | «Claude сильнее, ChatGPT на каждый день» |
| Длинный контекст больше 272K | Opus 5 | у Sol за этим порогом вход вдвое дороже |

Для нашей таблицы: `simple`, `standard`, `deep` и `code` совпадают с мнением сообщества. Кандидат на пересмотр после интеграции с Codex: фоновые задания класса `deep`/`code`, которые идут долго и без человека; их стоит сравнить на замерах с Codex. Для голосового пути критерии в порядке важности: задержка первого токена, реакция на перебивание, точность вызова инструментов.

Источники: [Ask HN: Claude Code or Codex?](https://news.ycombinator.com/item?id=48989357), [Ask HN: Codex on par?](https://news.ycombinator.com/item?id=47750069), [DataCamp: Opus 5 vs GPT-5.6 Sol](https://www.datacamp.com/blog/claude-opus-5-vs-gpt-5-6-sol), [Reddit consensus](https://tygartmedia.com/claude-vs-chatgpt-reddit/), [Retell: LLM для голоса](https://www.retellai.com/blog/best-llm-for-voice-ai-agents), [Haiku 4.5 vs GPT-4o mini](https://www.kunalganglani.com/blog/claude-haiku-vs-gpt-4o-mini).

## Нижняя планка класса для наборов (23.09.2026)

Звонок 23.09.2026 07:05: «Открой на маке калькулятор и посчитай 5 умножить на 24». Jev выбрал набор `computer` (0,98) и класс `simple` (0,84). Gemini Flash Lite не вызвала `computer_start`, а ответила «хм, секунду. Считаю на маке». Проверка честности эти слова не знала. Потом голосовая модель сама ответила «Да» на «Ты отправил задачу?», не спросив бэкенд. Правки: у набора в `packs.ts` есть `minTier`; для `computer` и `tasks` это `standard`, маршрут поднимает класс до планки. В `delegation/honesty.ts` добавлены «открою/открыл», «запущу/запустил», «посчитаю/считаю», «сделаю/сделал». Правило бэкенда для Mac: ясную задачу сразу отдавать `computer_start`, не зачитывая. Голосовой модели: на вопросы о заданиях всегда спрашивать бэкенд.

Решение владельца 23.09.2026, в тот же день: простую задачу на Mac выполнять как можно быстрее, сложную обсуждать. Карточка Jev у `computer_start` с `verbatim` (первое исключение из правила «быстрый путь только для read»): если Jev выбрал `computer_start` с вероятностью от 0,9 и класс `simple`, ядро само зовёт инструмент без LLM. Задание — реплики пользователя после последнего ответа Волны дословно и до четырёх реплик перед ними, название — первые пять слов просьбы (`verbatimArgs` в `delegation/client.ts`). Во всех остальных случаях запрос идёт модели не слабее `standard` (планка `minTier`). По правилу бэкенда она запускает ясную простую задачу сразу. Сложную (несколько шагов или приложений, условия, недостающие данные) она обсуждает с пользователем, составляет задание, зачитывает и запускает после согласия. Ошибочный запуск ограничен: доступ к каждому приложению даётся отдельно, задание можно отменить голосом.

Решение владельца 23.09.2026, позже в тот же день, отменяет предыдущее: перед отправкой в работу Волна уточняет, а не идёт делать. Карточка Jev у `computer_start` снята, быстрого пути для действий больше нет (механизм `verbatim` в `registry.ts` и `client.ts` остался без пользователей). Правило бэкенда `backendConfirm` в `persona.ts` действует для `task_start`, `computer_start`, `agents_send` и `agents_start`, когда они есть в звонке. Если в просьбе чего-то не хватает, модель сначала уточняет. Потом одним вопросом пересказывает задачу, без «запускаю» перед вопросом, иначе сработает проверка честности. Инструмент зовётся после явного «да» на этот вопрос. Голосовой модели запрещено говорить «запускаю», пока бэкенд не ответил.

## Два вида работы: «Код» и «Работа» (23.09.2026)

Решение владельца: наборов и исполнителей стало слишком много. Теперь больших дел два вида, как табы Пульта.

- **Код** (набор `code`, бывший `agents`): всё про программирование идёт в Claude Desktop. Новый чат `agents_start`, сообщение в существующий `agents_send`, плюс `agents_list` и `agents_open`.
- **Работа** (набор `work`, бывшие `tasks` и `computer`): всё остальное делает Codex через Пульт. Это исследования, планы, разборы, сравнения и действия в приложениях Mac. Запуск `work_start`, дальше `tasks_list`, `task_cancel`, `tasks_call_back`. Исполнитель на Opus (`task_start`, `TASK_MODEL`) удалён. Перед удалением проверено, что Codex делает исследование с поиском в сети: ответ с источником за 11 с. Промпт Codex в Пульте (`ComputerJob.prompt`) разрешает работать без приложений.
- **Классы модели в звонке:** `simple` (Gemini Flash Lite) и `standard` (Sonnet). Класс `deep` и Opus убраны (`CLIENT_MODEL_DEEP` больше не читается): что требует долгой мысли, уходит в «Работу». `standard` со всеми инструментами — верхняя ступень, `escalate` там не предлагается.

Таблицы и планы выше про `deep`, `computer`, `tasks` и Opus остаются как история решений.

## Техкарта — единица маршрута (25.09.2026)

Решение владельца 25.09.2026 отменяет наборы (`packs.ts` удалён). Таблицы и планы выше про наборы остаются как история. Схема на холсте [«Волна: техкарты как единица маршрута»](https://draftwall.vercel.app/c/skills-routing-7669), доски в `docs/design/canvas/skills-routing/`. Устройство кода: [core.md, 4h](core.md#4h-клиентское-делегирование).

**Что решено**

- Всё, о чём можно попросить, — техкарта (скилл в формате Agent Skills, в Волне «техкарта»). Нынешние наборы стали встроенными техкартами в `core/skills/`: `time`, `about-wave`, `memory`, `planner`, `contacts`, `web`, `code`, `work`, `history`, `techcards` (с 26.09.2026 `code` слита в `work`). Они помечены `metadata.system: "true"` и на экран «Память» не выводятся.
- Инструменты техкарты перечислены в стандартном поле `allowed-tools`. Уровень записан в `metadata.tier` (`simple` | `standard` | `work`). Отдельный файл `volna.yaml` не нужен: входы берутся из схемы инструмента, путь `instant` — из карточки Jev, запуск работы — из паспорта (`startsWork`).
- Функциями без техкарты остаются управление звонком (`end_call`), служебные функции маршрута (`escalate`, `offer_work`, `start_offered_work`) и функции техкарт (`techcard_*`, `always`). Права и защита живут в паспорте функции, а не в тексте техкарты: текст правится голосом и агентом.
- Уровень решается при создании техкарты и служит нижней планкой класса. Jev спрашивает класс всегда, но техкарта его поднимает. У `work` планка `standard`: звонок 26.09.2026, «посмотри пять последних файлов в загрузках» Jev счёл простым (0,95), Gemini Flash Lite ответила «нет доступа», а со второй попытки переврала задачу в «составить план реализации». Следующий звонок в тот же день показал, что дело не только в лёгкой модели: Luna 5.6 на ту же просьбу звала `escalate`, а со всеми инструментами отвечала «не вижу файлы на твоём Mac». Правила работы для T3 перечисляли только исследование, план и разбор. Теперь они коротко описывают, что умеет исполнитель: агент на Mac с файлами, терминалом и интернетом делает почти всё, что делают на компьютере (файлы и папки, интернет, документы и данные, тексты, скрипты). Модель к тому же не уточняет очевидное вопросом с выбором, а сразу предлагает план. На стенде 4 из 4 прогонов предлагают работу с первого круга.
- Отбор эмбеддингами перед Jev не нужен (замер ниже).
- Большую работу модель не запускает, а предлагает. Волна чётко говорит план (что сделает и что получится) сразу с глагола, без вступлений вроде «Предлагаю так:» (26.09.2026), и спрашивает, делать ли. Что работа большая, долгая или фоновая, не говорит: это очевидно (решение владельца 26.09.2026, заменило «скажи, что это займёт время»). Выбора «быстро или в работу» нет. Запуск только после «да», его распознаёт Jev. Исключение (решение владельца 26.09.2026): работа, которая только смотрит (прочитать, найти, перечислить, сравнить, пересказать), запускается сразу. Модель ставит `readOnly: true` в `offer_work`, это разрешено только для `work_start`; ядро дописывает в задание «Только посмотреть: ничего не создавай, не меняй, не перемещай, не удаляй, не отправляй и не покупай; если без этого не сделать, спроси». Волна говорит, что делает, без вопроса. На стенде сразу запустились «пять последних файлов в загрузках», «PDF в документах за месяц», «сравни цены», «краткое содержание PDF»; «удали dmg» и «переименуй скриншоты» остались предложением. Запрет в задании — просьба к агенту, а не техническая защита: у «Штурвала» нет режима только для чтения. Первый звонок с этим (26.09.2026 13:38): ядро запустило сразу, но Live, не дождавшись ядра, сам сказал «Проверю загрузки и назову пять последних файлов, сделать?»; а на «перезвони, когда закончишь» модель запустила второе такое же задание с `callback: call` вместо `tasks_call_back`. Теперь Live запрещено самой пересказывать план и спрашивать «сделать?», пока бэкенд не ответил; модель в системной инструкции видит работу, уже запущенную в этом звонке, с запретом запускать её повторно; «вопрос Волны» для `agreed` — только реплика, которая кончается «?».
- Работа идёт в «Штурвале» (до 05.10.2026 в T3 Code) ([core.md, 4l](core.md#4l-штурвал-работа-в-тредах)); Claude Desktop и Codex через Пульт выключаются конфигом (`HELM_TOKEN`), код остаётся.
- Новую техкарту пишет агент со скиллом skill-creator от Anthropic, без форка; правила Волны идут в задании ([skills.md, 8](skills.md#8-новая-техкарта-голосом)).

**Маршрут одного делегирования**

1. Jev, один запрос, ~0,3 с: `tool`, `techcard`, `tier`, при надобности `missing` и `agree`.
2. «Да» на предложенную работу → ядро запускает её само (`offer.start`).
3. Уверенный читающий инструмент с карточкой → ответ без модели (`jev`).
4. Простой техкарте с меняющим инструментом не хватает главного (что, когда, кто, какое) → Live спрашивает сам, без модели (`ask`).
5. Иначе модель класса с инструментами техкарты и её текстом. На `simple` удачное изменение с первого круга сразу уходит Live (`fill`, на один круг модели меньше). Если нужна работа — `offer_work`.
6. Лестница вверх: Flash Lite → `escalate` → Luna 5.6 (до 25.09.2026 Sonnet) со всеми инструментами → `offer_work` → «Делаем?» → «Штурвал».

**Меньше кругов и Luna напрямую (30.09.2026).** В прогоне выше 13 из 46 просьб шли в 2–4 круга: `current_time` первым кругом, хотя время в инструкциях (5), `escalate` перед `offer_work` на новостях и «регламенте» (4), чтение памяти и пересказ (4). Правки: `current_time` скрыт от модели (`ClientDelegateOptions.hidden`), в узкой техкарте правило «интернет, файлы, компьютер — сразу `offer_work`, а не `escalate`», Luna идёт напрямую в Responses API OpenAI (`backendModel`). Тот же прогон, Luna в обоих классах, размышления по умолчанию, по 4 раза на путь:

Эскалаций и `current_time` после правок нет, погода и новости за один круг, выдумок нет. Напрямую круг короче на 0,4–0,6 с (на коротком запросе разница 0,1 с: выигрыш растёт с длиной инструкций), но дважды на ~150 запросов OpenAI отвечал долго: 9 с и обрыв по таймауту 20 с с повтором прохода.
