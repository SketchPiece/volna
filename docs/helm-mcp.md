# Helm MCP: «Штурвал» из Claude владельца

Сделано 14.10.2026 (решение владельца: часть ядра, а не отдельный сервис). Ядро отдаёт удалённый MCP-сервер на `/mcp`; владелец подключает его в своём Claude (Desktop, мобильный, claude.ai) как custom connector и оттуда видит, какая работа идёт в «Штурвале», читает треды и пишет в них. Код в `core/src/mcp/`. Прототип отдельного сервиса (14.10.2026, `~/.helm/scratch/2026-10-14-helm-mcp-…`) больше не нужен: набор инструментов и правила взяты оттуда, коннектор на Mac заменён «Узлом».

## 1. Как идёт вызов

```
Claude (облако Anthropic) ── HTTPS + OAuth ──▶ ядро /mcp ── T3Client ──▶ «Узел» ══ WebSocket ══▶ «Штурвал» на Mac
```

- Инструменты ходят в «Штурвал» тем же клиентом, что «Работа» (`helm/client.ts`): снимок `shell`, снимок треда `bounded`, RPC `launchThread` и `dispatchCommand`. В облаке это вызовы «Узла» (`t3.request`, `helm.rpc`), и они проходят его белый список ([relay.md, 3](relay.md#3-безопасность)). Своих операций Helm MCP добавил «Узлу» две: снимки тредов с `:` и `%` в id (0.4.1) и команды settle/snooze (0.4.2).
- Отсюда ограничения: нет поиска по содержимому тредов (только по заголовкам), чтение треда — последнее окно `bounded`, а не вся история; новый тред только в папке проекта (без worktree), режим разрешений как у «Работы» (`HELM_RUNTIME_MODE`, `full-access` никогда); разрешения агентам (команда, правка файлов) здесь не даются — только в «Штурвале» на Mac или в телефоне.
- MCP без сессий и SSE: каждый `POST /mcp` — один JSON-RPC запрос (или пачка), ответ JSON. Методы: `initialize`, `ping`, `tools/list`, `tools/call`. `GET` и `DELETE` на `/mcp` отвечают 405.

## 2. Инструменты и правила

Чтения: `helm_overview` (на связи ли компьютер и все живые треды по проектам — с него начинать), `helm_list_projects`, `helm_list_unsettled_threads` (неразобранные треды, список по умолчанию: правило 4 в `INSTRUCTIONS` велит брать его; ровно как в приложении — только треды верхнего уровня и без отложенных, `includeSnoozed` / `includeChildren` добавляют отложенные и дочерние), `helm_list_threads` (все треды верхнего уровня, и разобранные, и отложенные, только когда нужны разобранные; `includeChildren` — с дочерними). Дочерние треды — субагенты и делегированные задачи (`lineage.relationshipToParent: subagent` или id `thread:provider:…` / `thread:delegated-task:…`); у каждого треда в списках есть `parentThreadId`, `helm_search_threads` (по заголовкам), `helm_read_thread` (состояние, последние сообщения, что агент делал, вопросы и запросы разрешений), `helm_list_questions`.

Запись: `helm_send_message` (в идущий ход или новым, как `work_send`), `helm_start_thread` (модель проекта, по желанию режим плана), `helm_interrupt_thread`, `helm_answer_question` (ответ словами владельца, сопоставляется с вариантами как в звонке, `buildAnswers`), `helm_settle_thread` (разобрать тред или вернуть в активные, `thread.settle`/`thread.unsettle`), `helm_snooze_thread` (отложить до времени с поясом владельца, не дальше года, или разбудить, `thread.snooze`/`thread.unsnooze`). Settle и snooze меняют только место треда в списке «Штурвала», работу агента не трогают; в списках тред помечен `settled` и `snoozedUntil`.

Правила, ради которых сервер сделан (в `INSTRUCTIONS` при `initialize` и в описаниях инструментов):

1. Сообщение агенту — дословно словами владельца, на его языке: без переписывания, дополнения, перевода и «большого промпта». Неясно, что слать, — спросить владельца.
2. Запись только после явного «да». Первый вызов ничего не делает: возвращает превью и код подтверждения, подписанный по точным аргументам (устойчивый JSON + HMAC, 15 минут, одноразовый). Исполняет только повторный вызов с тем же набором аргументов и кодом. Другие аргументы, чужой или использованный код — отказ. Превью проверяет, что тред или проект есть и компьютер на связи, иначе спрашивать не о чем.
3. Список по умолчанию — неразобранные треды (`helm_list_unsettled_threads`); все треды — только по просьбе владельца или если нужного треда среди неразобранных нет.
4. Плюс MCP annotations (`readOnlyHint`, `destructiveHint` у остановки): Claude сам спрашивает разрешение на запись. `MCP_CONFIRM_WRITES=client` оставляет только это, без кода.

Лог ядра пишет только `mcp.call tool=… ok=… ms=…`, без аргументов и текстов.

## 3. Вход

Минимальный OAuth 2.1 на одного владельца, как ждут custom connectors Claude (`mcp/oauth.ts`), вход пасскеем:

- `/.well-known/oauth-protected-resource[/mcp]`, `/.well-known/oauth-authorization-server`; `/mcp` без токена отвечает 401 с `WWW-Authenticate: Bearer resource_metadata=…`.
- `POST /register` (DCR, адреса возврата только https или loopback); `POST /token` — `authorization_code` с PKCE S256 и `refresh_token`. Токен доступа на час, обновления на 90 дней.
- Разрешает владелец пасскеем (с 19.10.2026, `mcp/passkey.ts`, страницы в `mcp/pages.ts` по холсту `docs/design/canvas/helm-mcp-passkey`, на английском). Пароль `MCP_OWNER_PASSWORD` годится один раз: пока пасскея нет, `GET /authorize` (или отдельная страница `/passkey`, чтобы настроить заранее) спрашивает пароль (10 неверных за 15 минут на всё ядро — пауза) и сразу предлагает создать пасскей; код входа клиент получает только после создания. Когда пасскей есть, `/authorize` показывает только кнопку пасскея (`POST /authorize/passkey`), а пароль сервер отклоняет с 403. Формы и вызовы пасскея принимаются только со своего `Origin`.
- WebAuthn без библиотеки: аттестация `none`, ключ из `getPublicKey()` браузера (SPKI; ES256, EdDSA, RS256), обязательная проверка владельца (флаг UV), домен — хост ядра (`volna-core.up.railway.app`; смена домена — новый пасскей). Вызов подписан билетом `passkey` вместе с параметрами OAuth, одноразовый, 10 минут.
- Пасскей лежит в `MEMORY_DIR/helm-mcp-passkey.json` (на Railway `/data`). Сброс — удалить файл (`railway ssh --service core -- rm /data/helm-mcp-passkey.json`): следующий вход снова спросит пароль. Испорченный файл — ошибка входа, а не возврат к паролю.
- Базы нет (кроме файла пасскея): регистрации, коды и токены подписаны `MCP_SIGNING_SECRET` (вид токена входит в подпись). Смена секрета отзывает все входы. Одноразовость кодов — в памяти до их срока.
- Общее правило ядра «браузерам 403» (`http/guards.ts`) не действует на пути Helm MCP (`/mcp`, `/authorize`, `/token`, `/register`, `/.well-known/oauth-*`), и только когда он включён: у них своя авторизация, платного в них нет, а форма `/authorize` принимается только со своего `Origin`.

Иконка коннектора — иконка «Штурвала» (`core/assets/helm-icon.png` из `docs/design/icons/helm`): в `serverInfo.icons` при `initialize` и по `/icon.png`, `/favicon.ico`, `/apple-touch-icon.png`.

## 4. Настройка

Переменные ядра (Railway, сервис `core`):

| Переменная | Что |
|---|---|
| `MCP_OWNER_PASSWORD` | Пароль владельца, от 12 символов: один раз, чтобы создать пасскей |
| `MCP_SIGNING_SECRET` | Секрет подписи, от 32 символов (`openssl rand -base64 48`) |
| `MCP_PUBLIC_URL` | Необязательно: внешний адрес; по умолчанию `https://$RAILWAY_PUBLIC_DOMAIN`, локально — из запроса |
| `MCP_CONFIRM_WRITES` | `server` (по умолчанию, двухшаговая запись) или `client` |

Нужна «Работа» (`RELAY_TOKEN` в облаке или `HELM_TOKEN` на Mac); без неё маршрутов нет. Строка `Helm MCP:` в логе запуска говорит, включён ли он.

Подключение: Claude → Settings → Connectors → Add custom connector → `https://your-core.example.com/mcp`, вход паролем владельца. Коннектор общий для аккаунта, поэтому работает и в мобильном Claude.
