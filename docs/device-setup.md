# Запуск на реальном iPhone

На 21.09.2026 подписанная Debug-сборка установлена на подключённый iPhone 15 Pro Max (iOS 27.0). Developer Mode включён, Siri-extension подписан и установлен вместе с приложением. HTTPS-адрес передан по USB и сохранён на устройстве; токен сохраняется в Keychain. В 22:11 установлена новая версия с переносом системного SiriKit/CallKit-пути из Zorava. Обычный разговор и Siri были подтверждены в предыдущей версии; новой версии нужна проверка на устройстве, включая блокировку.

## Сейчас

Откройте Волна → «Позвонить Волне» и разрешите микрофон. После ответа попробуйте вторую реплику и перебивание, затем завершите звонок. Оранжевый индикатор микрофона должен погаснуть.

С 25.09.2026 iPhone подключается к Mac напрямую, без туннеля: ядро слушает `0.0.0.0:8789` (`HOST=0.0.0.0` в `core/.env.device`), в приложении адрес `http://Sketch-MacBook-Pro.local:8789` (имя Bonjour из `scutil --get LocalHostName`; не зависит от смены IP). Работает, только пока iPhone в той же Wi-Fi, что и Mac; по мобильной сети — через ngrok (ниже). Обычный http приложение разрешает только для адресов локальной сети (`ConnectionSettings.isLocalNetworkHost`: `*.local`, 10/8, 172.16/12, 192.168/16, 169.254/16); токен ядра в такой сети идёт открытым текстом. При первом подключении iOS спрашивает доступ к локальной сети — его нужно разрешить. Консоль ядра (`127.0.0.1:25452`) из сети по-прежнему недоступна. Mac должен оставаться включённым и не спать. USB после установки для звонка не нужен.

## Повторный запуск ядра после перезагрузки Mac

Из каталога проекта в первом терминале:

```sh
cd core
node --env-file=.env --env-file=.env.device src/main.ts
```

Для звонков вне дома, во втором терминале:

```sh
ngrok http http://127.0.0.1:8789 --inspect=false
```

Используется уже созданный локальный `core/.env.device`: порт, loopback-адрес и случайный `BRIDGE_TOKEN`. Он исключён из Git и доступен только владельцу файла. API-ключ остаётся в `core/.env`. Не публикуйте эти файлы. Не запускайте второй экземпляр поверх уже работающего.

Чтобы переключить адрес (локальная сеть или ngrok), поменяйте его в настройках приложения (режим отладки). Токен менять не нужно. Либо подключите разблокированный iPhone по USB и выполните:

```sh
xcrun devicectl list devices
python3 ios/scripts/configure-device.py --device ИДЕНТИФИКАТОР --url http://Sketch-MacBook-Pro.local:8789
```

Для ngrok вместо адреса Mac передайте `https://АДРЕС.ngrok-free.app`.

Скрипт передаёт адрес и существующий токен через окружение запуска, без вывода секрета и без встраивания его в приложение. Это работает только в Debug-сборке. Настройки сохраняются и используются при обычном запуске, включая запуск через Siri.

## Перезвон Волны и уведомления (APNs)

Чтобы Волна могла сама позвонить по готовому фоновому заданию или прислать уведомление, ядру нужен ключ APNs. Без ключа итоги всё равно работают: Волна скажет их в звонке или в начале следующего.

1. В Apple Developer → Certificates, Identifiers & Profiles → Keys создайте ключ с галочкой «Apple Push Notifications service (APNs)». Скачайте `.p8`: скачать его можно только один раз. Запишите Key ID и Team ID.
2. Положите `.p8` рядом с ядром (например, `core/data/apns.p8`; каталог `data/` не попадает в Git) и добавьте в `core/.env`:
   ```sh
   APNS_KEY_PATH=data/apns.p8
   APNS_KEY_ID=ABC123DEFG
   APNS_TEAM_ID=XYZ987TEAM
   ```
   `APNS_TOPIC` по умолчанию `dev.prototype.callassistant`, bundle id приложения.
3. У App ID должна быть включена возможность Push Notifications. В entitlements приложения уже есть `aps-environment`. При автоматической подписи Xcode добавит возможность сам; если сборка на iPhone ругается на профиль, включите Push Notifications в Signing & Capabilities.
4. Запустите приложение на iPhone и разрешите уведомления. Оно само пришлёт токены ядру (`POST /push/register`), в логе приложения `push.register status=200`. При старте ядро пишет `Tasks: … APNs … (call back and notify)`.

Проверка: попросите Волну сделать что-то долгое фоном и выберите «перезвонить», затем положите трубку. Когда задание будет готово, iPhone зазвонит «Волна». Если не ответить за 40 с, придёт уведомление.

## Siri

1. В Волна → Настройки нажмите «Разрешить Siri».
2. Разрешите микрофон и выполните один звонок кнопкой. Завершите его. Для системного звонка произнесите вслух «Позвони Волне через Волну» / «Call Volna using Volna». SiriKit получает словарь единственного AI-адресата и локализованные примеры; контакт в адресной книге не нужен.
3. Приложение читает язык Siri через `INPreferences.siriLanguageCode()` и обновляет подсказку при возвращении на экран. Язык Siri может отличаться от языка приложения. На английском локализованное системное имя — Volna, на русском — Волна; добавлены варианты имени для Siri, включая «Волне».
4. Проверьте фразу через Siri, вызванную боковой кнопкой, затем повторите с заблокированным экраном, отвернув его от лица. Старое foreground-действие CallGPTIntent удалено из текущей сборки после подтверждённого выбора этого действия Siri. Если в «Командах» остался пользовательский «Call Volna» / «Позвони Волне», переименуйте его, чтобы название не перехватывало системный звонок. Для проверки используйте фразу из пункта 2.

Если Siri просит разблокировку, зафиксируйте точную фразу и результат: это отдельная проверяемая гипотеза, а не гарантированное свойство прототипа. Полная матрица — [device-checklist.md](device-checklist.md).

## Что проверено автоматически

- Подписанная сборка, установка и запуск на физическом iPhone.
- Сохранение HTTPS-адреса в настройках установленного приложения.
- HTTPS health-check; запрос без токена отклоняется с 401, с верным токеном проходит авторизацию.
- Запись запросов в локальном инспекторе ngrok отключена. Через ngrok проходят SDP и токен ядра; аудио идёт по WebRTC напрямую в OpenAI, API-ключ ngrok не передаётся.

Пользователь подтвердил настоящий голосовой разговор в предыдущей версии на iPhone 21.09.2026: ответ слышен, разговор продолжается. Ранние варианты запуска с блокировки требовали разблокировки. Позже контрольная Zorava успешно воспроизвела сигналы без разблокировки; этот путь перенесён в Волну, но Realtime-разговор с блокировки пока не подтверждён. Перебивание и AirPods отдельно не проверены.

После исправления передачи управления из App Intent пользователь подтвердил запуск из Shortcuts и голосом через Siri. Подробности — [siri-investigation.md](siri-investigation.md).
