# Синхронизация работы: задания Волны и треды «Штурвала»

План от 26.09.2026, решения владельца записаны в разделе 1. Этапы 1, 2 и 4 и часть этапа 3 в ядре сделаны 26.09.2026 (ветка `task-sync-impl`), проверены только тестами на поддельном T3; экран телефона ждёт доски. Как сделано и чем отличается от плана — раздел 11. Устройство ядра в [core.md, 4i и 4l](core.md#4l-штурвал-работа-в-тредах), инварианты в [architecture.md, 7](architecture.md).

С 05.10.2026 треды живут в «Штурвале» (Helm, форк T3 Code): ниже, где речь о нынешнем устройстве, он и назван. В ядре модуль `core/src/helm/`, поля задания `helmThread`, `helmProject`, `helmPending`; прежние `t3Thread`, `t3Project`, `t3Pending` в старом `tasks.json` читаются и при загрузке переводятся в новые. Коды ошибок `helm_*`, переменные `HELM_*` (прежние `T3_*` читаются как запасные).

## 1. Решения владельца (26.09.2026)

- Вся работа идёт через T3 Code (с 05.10.2026 — через «Штурвал»). Астра (Codex через Пульт) не нужна.
- Пульт deprecated: не развивается, ядро его в синхронизацию не включает ([mac-agent-hub.md](mac-agent-hub.md)).
- На телефоне в «Работе» показываются и собственные треды владельца в «Штурвале», не только задания Волны.
- Голосом, после пересказа и «да», Волна может отменить ход в любом треде и дописать сообщение в собственный тред владельца.
- Разрешения (approvals) агенту в «Штурвале» голосом по-прежнему не даются.
- Доступ к «Штурвалу» из сети не закрывается.

## 2. Что есть сейчас

- Задания Волны (`work_start`) живут в `core/data/tasks.json` (16 hex, последние 50 законченных) и выполняются в тредах T3 (`task.t3Thread`). Их видят голос (`tasks_list`), iPhone (`GET /tasks`, «Работа») и таб Пульта (`PUT /tasks/{id}`).
- Собственные треды владельца ядро видит только по запросу голосом: `work_threads`, `work_send`, `work_answer` читают `GET /api/orchestration/shell`. На телефоне их нет, об их вопросах Волна молчит.
- Разрывы:
  1. При перезапуске ядра задания `running` становятся `failed/interrupted`, хотя тред в T3 работает дальше.
  2. Лимит раннера 10 минут обрывает долгую работу в T3.
  3. `t3Thread` записывается после `thread.create`: сбой между ними оставляет тред без задания.
  4. Отменить ход можно только у задания Волны.

## 3. Границы

Синхронизация даёт один список и ссылки, а не копирует исполнение: работа идёт только в «Штурвале», ядро её читает и передаёт команды владельца.

- **Входит:** задания Волны и все неархивные треды всех проектов «Штурвала».
- **Не входит:** Пульт, Астра, сессии Claude Desktop и Codex; тексты сообщений, промпты, дифы. Наружу идут только заголовок, проект, статус, чего ждёт, фраза хода и короткий итог.
- **Источник правды:** «Штурвал» для состояния треда; ядро для связей, `delivery` («итог услышан») и скрытия из списка.
- Ядро не создаёт, не архивирует и не удаляет треды ради синхронизации. Новый тред по-прежнему только через `work_start`.

## 4. Модель данных

Модуль `core/src/work-sync/`, реестр `core/data/work-items.json` (атомарная запись, как у `TaskStore`). Реестр можно пересобрать из `tasks.json` и `shell`, поэтому его потеря не страшна.

```ts
WorkItem {
  id: string                 // helm:<threadId>; у задания Волны без треда — task:<taskId>
  origin: 'volna' | 'owner'  // кто начал: work_start или владелец в окне «Штурвала»
  task?: string              // id задания Волны
  thread?: string            // UUID треда «Штурвала»
  project?: { id: string; title: string }
  title: string              // ≤ 120
  status: 'queued' | 'working' | 'needs_you' | 'idle' | 'done' | 'failed' | 'cancelled' | 'gone'
  waiting: { kind: 'question' | 'approval'; text: string } | null
  progress: string | null
  result: string | null      // ≤ 600, только для заданий Волны
  error: string | null       // только код
  source: { updatedAt: string; turnId: string | null }
  stale: boolean             // «Штурвал» не отвечает, показано последнее известное
  hidden: boolean
  createdAt: string; updatedAt: string; finishedAt: string | null
}
```

Ключ записи — id треда. Связь задания и треда только по точному `task.helmThread`, никогда по заголовку. `Task` получает флаг `helmPending`: id треда записан, `thread.create` ещё не подтверждён.

## 5. Статусы

| T3 | Статус |
|---|---|
| `hasPendingUserInput` или `hasPendingApprovals` | `needs_you` |
| `latestTurn.state = running`, `session.status` `running`/`starting` | `working` |
| `latestTurn.state = error` или `session.status = error` | `failed` |
| ход закончен (`completed`, `interrupted`) у собственного треда | `idle` |
| `archivedAt` или тред пропал из `shell` | `gone` |

Задание Волны сохраняет свои статусы (`queued`, `done`, `failed`, `cancelled`) по правилам `helm/worker.ts`; пока оно идёт, статус считается по таблице. Если владелец продолжил законченное задание в том же треде, задание остаётся `done`, а запись показывает `working` с новым ходом.

Правило `threadState()` из `helm/tools.ts` выносится в общий модуль, чтобы голос и список не расходились.

**Обновление:** один опрос `shell` раз в 10 с, пока идёт звонок или есть `working`/`needs_you`, иначе раз в 60 с. Опрос своего треда в `helmWorker` (2,5 с) остаётся для хода и итога. WebSocket-подписка «Штурвала» — позже, отдельным шагом.

## 6. Направления

- **«Штурвал» → ядро:** только чтение (`shell`, `threads/:id`).
- **Ядро → «Штурвал», только по просьбе владельца голосом после пересказа и «да»:** `work_send` (сообщение в любой тред), `work_answer` (ответ на вопрос), отмена хода (`thread.turn.interrupt`) в любом треде. Разрешений нет.
- **Ядро → iPhone:** `GET /tasks` отдаёт записи реестра, добавляются `origin` и `waiting`.
- **Ядро → голос:** `tasks_list` отдаёт тот же список; новый `needs_you` объявляется в живом звонке одной фразой.
- **Ядро → Пульт:** выключается (`pult-sync.ts` не подключается).

## 7. Конфликты, дубликаты, ошибки

- **Устаревшие снимки:** снимок с более старым `updatedAt` или `turnId` не применяется (гонка общего опроса и опроса `helmWorker`).
- **Команда не меняет статус:** отмена шлёт `interrupt`, статус меняется, когда «Штурвал» покажет `interrupted`.
- **Двойной ответ** голосом и в окне «Штурвала»: второй «Штурвал» отклонит как stale pending, Волна говорит «уже ответили в окне «Штурвала»».
- **Технические дубли** исключены: ядро само генерирует UUID треда, сначала пишет его в задание (`helmPending`), потом шлёт `thread.create`; `commandId` идемпотентен.
- **Смысловые дубли:** перед `offer_work` ядро ищет идущие треды того же проекта с похожим заголовком (нормализация и транслитерация, как в `helm/projects.ts`) и предлагает дописать туда. Само ничего не сливает.

| Ситуация | Поведение |
|---|---|
| «Штурвал» не отвечает | `stale: true`, статусы не меняются; `tasks_list` говорит, на какое время данные; одна строка `sync.helm.offline` в логе |
| `helm_unauthorized` | опрос останавливается, телефон показывает одну строку «Нет доступа к «Штурвалу»» |
| `helm_incompatible` | только чтение, команды не шлются (уже так в `#ensureCompatible`) |
| перезапуск ядра | задание с `helmThread` снова берётся под наблюдение, а не `interrupted`; с `helmPending` и без треда в `shell` — `failed/interrupted` |
| долгая работа | для «Штурвала» вместо 10 минут `HELM_TASK_MAX_MINUTES` 2 ч и `failed/helm_stalled` после 20 мин без активностей |
| тред пропал или в архиве | запись `gone`; задание Волны `failed/helm_thread_lost` |
| битый реестр | переименовать в `.corrupt-<ts>`, пересобрать |

## 8. Безопасность

- Токен «Штурвала» только в `core/.env`, не в логе; синхронизация пользуется двумя читающими эндпоинтами и тремя существующими командами.
- Телефон получает список по токену ядра (Keychain). Заголовки собственных тредов могут быть личными: наружу только заголовок, проект, статус, вид ожидания; сообщения нет.
- Фраза хода для собственных тредов не строится (лишние деньги и пересказ содержимого); только у заданий Волны.
- Голосом нельзя: разрешения в «Штурвале», доступ к папкам, проект из существующей папки.
- В лог только id, статусы, коды ошибок, версия «Штурвала»; тест проверяет, что `title`, `progress`, `result` в лог синхронизации не попадают.
- «Штурвал» остаётся доступен из сети (решение владельца); список тредов наружу идёт только через ядро с его токеном.

## 11. Как сделано (26.09.2026)

Устройство: [core.md, 4l и 4n](core.md#4n-один-список-работы-задания-волны-и-треды-штурвала). Живьём не проверено; сценарии Д-18–Д-20, Д-30, Д-31, Э-17 в [test-protocol.md](test-protocol.md) (номер Э-16 из плана занят плагинами).

- **Этап 1 сделан.** `helmPending`, `TaskRunner.resume()`, `HELM_TASK_MAX_MINUTES` (120) и `HELM_STALL_MINUTES` (20), зависший ход останавливается `interrupt`. «Работа» только с `HELM_TOKEN` (или через «Узел»); `pult-sync` и `pultComputer` удалены из ядра 27.09.2026 вместе с Пультом. С 05.10.2026 треды живут в «Штурвале» (форк T3 Code; с 05.10.2026 ядро на его протоколе 2, `helm-cloud/docs/relay.md`, раздел 2.1).
- **Этап 2 сделан с упрощением:** реестр в памяти, без `work-items.json`. Всё в нём собирается из `tasks.json` и `shell`, а единственное, что пришлось бы хранить, — `hidden`, которому нужен экран. Без файла нет и строки «битый реестр». Поля `source`, `hidden`, `createdAt` не заведены; вместо `source.updatedAt` сравнивается `updatedAt` треда.
- **Собственный тред, пропавший или ушедший в архив,** просто исчезает из списка; `gone` только у идущего задания Волны, чей тред пропал (при живом «Штурвале» и без `helmPending`).
- **Этап 3, часть в ядре:** `tasks_list` отдаёт `threads` и `helm.asOf`, вопрос или разрешение собственного треда объявляется в звонке. `GET /tasks` не менялся: телефон ждёт статусы только заданий, новые `needs_you` и `idle` без доски он показал бы неверно. Для экрана есть `GET /work`.
- **Этап 4 сделан:** `work_stop` (любой тред, с пересказом и «да»; тред идущего задания отменяет задание), `already_answered`, похожая работа перед предложением (`offer.similar`). Транслитерации в сравнении заголовков нет: только основы слов.
- **Открытые вопросы раздела 10:** собственные треды показываются идущие, ждущие и за сутки (предложение принято); уведомления вне звонка нет (вопрос в [pending.md](pending.md)); диплинк на тред не искали.
- **Перезвон в назначенное время** (`callbacks/`) подключается в том же блоке, что и задания, поэтому с 27.09.2026 ему тоже нужен `HELM_TOKEN` (и ключ APNs, как раньше).
