# Техкарты в формате скиллов

Решение владельца 23.09.2026: техкарта использует формат скилла ([Agent Skills](https://agentskills.io), как в Claude и Codex). Поэтому к Волне подключаются скиллы из интернета и свои. В интерфейсе и в речи это по-прежнему «техкарта». Поведение для владельца описано в [memory-design.md, 7](memory-design.md#7-техкарты), здесь устройство. Код лежит в `core/src/skills/`.

## 1. Формат

Техкарта — это папка с файлом `SKILL.md`:

```markdown
---
name: razrabotka-volny                        # строчная латиница, цифры, дефисы; до 64 знаков
description: "когда владелец просит поправить Волну"   # что это и когда применять; видит бэкенд
metadata:
  title: "Разработка Волны"                   # название в интерфейсе; без него показывается name
  origin: "volna"                             # заведена голосом
---

# Разработка Волны

Инструкции автора скилла (у скилла из интернета они есть, у голосовой техкарты нет).

## Правила владельца

1. Репозиторий CallAssistant
2. Сначала HTML-макет
```

- Рядом с `SKILL.md` могут лежать `references/`, `assets/` и `scripts/`. Бэкенд читает текстовые файлы через `techcard_read` с параметром `file`, путь допускается только внутри папки скилла.
- **Скрипты ядро не запускает никогда.** Скилл для Волны — это только текст.
- `allowed-tools` (стандартное поле, через пробел; маска `gmail_*` берёт все инструменты плагина) — инструменты, которые модель увидит, когда Jev выберет эту техкарту. Техкарта без них — только текст: модель читает её через `techcard_read`, но в маршрут она не идёт. Исключение (с 26.09.2026): техкарта, заведённая голосом (`metadata.origin: "volna"`), без `allowed-tools` идёт в маршрут со всеми инструментами звонка и планкой `standard`, Jev видит её как «название: описание» (`skills/routing.ts`).
- `metadata.tier`: `simple`, `standard` или `work` — уровень, решённый при создании; нижняя планка класса модели, `work` — большая работа, которую Волна предлагает сделать, с планкой `standard` ([tools-routing.md](tools-routing.md#техкарта--единица-маршрута-25092026)). Без него класс выбирает Jev.
- `metadata.system: "true"` — встроенная техкарта маршрута (время, планы, работа…): экран «Память» и список техкарт в инструкциях её не показывают. `metadata.route: "off"` — техкарта не прошла проверку на Jev и остаётся текстом.
- Остальные поля frontmatter (`license`, `compatibility`) ядро не использует, но сохраняет как есть.

## 2. Где лежат (источники)

| Источник | Папка | Кто пишет | Голос |
|---|---|---|---|
| builtin | `core/skills/` в репозитории | код, вместе с расширением (например, почта) | только правила поверх, слоем |
| external | `SKILLS_EXTRA_DIRS` в `core/.env` через запятую (например, `~/.claude/skills`) | владелец вне Волны | только правила поверх, слоем |
| plugin | `skills/` включённых плагинов в `data/plugins/<имя>` (раздел 7) | автор плагина | только правила поверх, слоем |
| owner | `core/data/skills/` (`MEMORY_DIR/skills`) | голос, агент со skill-creator (раздел 8) и `npm run skills -- add` | правила; у голосовых техкарт также название и описание |

- Если имя совпадает, скилл владельца заменяет скилл из другого источника.
- Если у скилла владельца стоит `metadata.overlay: "true"`, это слой: в нём только «Правила владельца» поверх встроенного или внешнего скилла. Инструкции автора остаются, правила владельца идут после них. Так расширение приносит заводские правила, а владелец дополняет их голосом, и код при этом не трогается.
- Папки перечитываются при каждом вызове. Скилл, положенный руками, виден со следующего звонка, перезапуск не нужен.
- История правок лежит в `data/skills/.history.json`, до 10 версий на техкарту.

## 3. Как правит голос

- `techcard_write(title, when, rules)` записывает **только раздел «Правила владельца»** и всегда целиком. Текст автора скилла из интернета голосом не меняется.
- Техкарта, заведённая голосом (`origin: volna`), получает новые `description` и `metadata.title`. У установленного скилла frontmatter пишется обратно байт в байт.
- Для встроенного или внешнего скилла `techcard_write` создаёт слой в `data/skills/<имя>`. `techcard_delete` удаляет этот слой, сам скилл остаётся.
- Инвариант прежний: правила владельца появляются только из его слов в разговоре. Извлечение после звонка и «сон» техкарты не трогают.

## 4. Установка из интернета

```sh
cd core
npm run skills                                   # список: имя, источник, описание, сколько правил владельца
npm run skills -- add https://github.com/<o>/<r>/tree/main/skills/pdf
npm run skills -- add ~/Downloads/my-skill        # папка с SKILL.md
npm run skills -- add <repo> <путь внутри>        # если в репозитории несколько скиллов, add покажет список
npm run skills -- remove pdf
npm run skills -- check <имя>                    # узнаёт ли Jev техкарту по evals/volna-routing.json (раздел 8)
```

`add` проверяет `name` и `description`, копирует папку без `.git` и не заменяет уже установленный скилл без `--force`. Скилл из интернета — чужой текст в инструкциях бэкенда. Ставить только те, которым доверяешь, как и в Claude Code.

## 5. Что видят модели и экран

- **Jev** (с 25.09.2026): выбирает техкарту маршрута по `description` среди тех, у кого хотя бы один инструмент из `allowed-tools` есть в звонке. Модель класса видит только её инструменты и её текст (инструкции автора и правила владельца, до 3000 знаков) прямо в системной инструкции. Маршрут техкарты уровня `work` получает ещё `techcard_read`: задачу исполнителю составляют по правилам владельца из других техкарт. Звонок 26.09.2026: «можешь изменять себя?», «твой внутренний код, систему» голос принял за просьбу сменить характер, а техкарта владельца «Добавление и изменение возможностей» (без `allowed-tools`) в маршрут не попадала; с тех пор голос и бэкенд отличают доработку Волны (возможности, код, система, техкарты) от характера и манеры речи (`assistant/persona.ts`).
- **Бэкенд:** в инструкциях список «название (описание)» несистемных техкарт, каждое описание не длиннее 240 знаков. Техкарту целиком он читает через `techcard_read` перед работой: инструкции автора (до 12 000 знаков), правила владельца, список файлов. На уровне «Холодная» инструментов техкарт в звонке нет. Правила владельца важнее инструкций автора.
- **Голосовая модель** техкарт не видит.
- **Экран «Память»:** `GET /memory` отдаёт `techCards` в прежней форме (`id` теперь имя скилла) и новое поле `source`. `DELETE /memory/techcards/:id` на встроенную или внешнюю техкарту отвечает 409. Экран пока не показывает источник и инструкции автора. Как их показать, решается через HTML-макет на одобрение.
- **«Забыть всё»** удаляет голосовые техкарты и слои. Установленные скиллы остаются: это не память о владельце.

## 6. Перенос

До 23.09.2026 техкарты хранились в `memory.json` (`techCards`). При старте ядро переносит их в `data/skills/<имя>` вместе с историей и очищает старый список. Схема `techCards` в `memory/model.ts` осталась только ради этого переноса.

## 7. Плагины

Техкарта может принести свой MCP-сервер. Единица поставки — плагин в формате плагинов Claude Code. Для людей это «линия» (решение владельца 27.09.2026, раздел 7.1). В коде название для людей задано в одном месте, `PLUGIN_WORDS` в `core/src/plugins/format.ts`, и пока там ещё «плагин»:

```
<имя>/
  .claude-plugin/plugin.json    name (как имя скилла), description, version
  skills/<техкарта>/SKILL.md    техкарты; allowed-tools называют инструменты плагина
  .mcp.json                     { "<сервер>": { "command", "args", "env" } | { "type": "http", "url", "headers" } }
```

- `.mcp.json` принимается в обеих формах (с обёрткой `mcpServers` и без), серверы можно держать и в `mcpServers` внутри plugin.json. Транспорты: stdio и streamable HTTP; `sse` и OAuth не поддерживаются, такой сервер пропускается.
- Подстановка как в Claude Code: `${CLAUDE_PLUGIN_ROOT}` — папка плагина, `${VAR}` и `${VAR:-запасное}` — из `core/.env`. Секреты ядра (`OPENAI_API_KEY`, `BRIDGE_TOKEN`, `PULT_TOKEN`, ключи OpenRouter и TypeSafe) не подставляются. Без обязательной переменной сервер не запускается.
- Инструменты сервера становятся инструментами ядра `<плагин>_<инструмент>` (строчная латиница, цифры, `_`, до 64 знаков). Эффект по подсказкам MCP: `readOnlyHint` → `read`, явный `destructiveHint: false` → `write`, иначе `act` (по спецификации MCP `destructiveHint` по умолчанию true). Схему аргументов модель видит как есть, проверяет её ядро.
- Техкарты включённого плагина идут в общий список с источником `plugin` (после external, до owner) и маршрутизируются как любые. Маска `gmail_*` берёт все инструменты плагина gmail. Если у плагина нет ни одной техкарты, `add` дописывает свою: описание из plugin.json, `allowed-tools: <плагин>_*`. Правила владельца на техкарту плагина ложатся слоем, как на встроенную.
- `allowed-tools` в форме Claude Code `mcp__server__tool` не переводится: в техкарте плагина пишется `<плагин>_<инструмент>` или `<плагин>_*`.

### 7.1. Для людей: «линии» и «коммутатор»

Решение владельца 27.09.2026. Образ взят из телефонии: Волне звонят, а сервисы к ней подключаются как линии на старой станции, где телефонистка втыкает штекер. Отклонены «Частоты», «Станции», «Каналы», «Кассеты» и «Лампы».

- Одна штука называется «линия»: «Почта», «Календарь», «GitHub». Во множественном числе — «линии», источник техкарты — «с линии».
- Экран, где линии подключают и отключают, называется «Коммутатор». Макета пока нет, он будет вместе с кнопкой включения на телефоне.
- Состояния: «на линии» (включено, сервер отвечает), «линия свободна» (включено, сейчас не используется), «обрыв» (сервер не поднялся, `changed` или истёк доступ; нужно включить или войти заново), «нет линии» (не подключено).
- Действия: «Подключить» и «Отключить».
- Речь Волны: «Почта не на линии», «Линия к календарю оборвалась». Подключение по-прежнему делается только кнопкой, не голосом (раздел ниже).
- В коде, файлах и командах остаётся `plugin` (`data/plugins`, `npm run plugins`): формат чужой, его имя не переводим.

### Включение — только на Mac

Включить плагин с MCP-серверами значит пустить чужой код на Mac или дать доступ к сервису, поэтому это решение **никогда не принимается голосом**. Пока включение делает только `npm run plugins -- enable`, кнопка на телефоне будет позже, со своим макетом. Включение запоминает отпечаток `.mcp.json`: если конфигурация серверов поменялась, плагин не грузится (`changed`), пока его не включат снова. Выключение доступ только забирает и действует сразу: техкарты пропадают со следующего вызова, инструменты отвечают `plugin_disabled`.

```sh
cd core
npm run plugins                                   # список: статус, техкарты, серверы, каких переменных нет в .env
npm run plugins -- add ~/.claude/plugins/marketplaces/claude-plugins-official/external_plugins/context7
npm run plugins -- add https://github.com/<o>/<r>/tree/main/plugins/<имя>
npm run plugins -- enable context7                # одобрить серверы; затем перезапустить ядро
npm run plugins -- check context7                 # запустить серверы и показать инструменты с эффектами
npm run plugins -- disable context7
npm run plugins -- remove context7
```

Плагин без серверов включается сразу при `add`: это только текст. Состояние хранится в `data/plugins/.state.json`. Почты пока нет: готового Gmail MCP-сервера с ключами на этом Mac нет (кандидаты не проверены: `@gongrzhe/server-gmail-autoauth-mcp`, `workspace-mcp`).

## 8. Новая техкарта голосом

Решение владельца 25.09.2026: новую техкарту или большую переделку пишет не Волна, а агент на Mac (исполнитель «Работы», в «Штурвале» — Claude) со скиллом skill-creator от Anthropic. Волна только передаёт просьбу и вопросы агента.

1. Владелец просит («заведи техкарту: когда говорю „отчёт за неделю“, собирай задачи и присылай сводку»). Jev выбирает техкарту «Техкарты», модель зовёт `offer_work` с `techcard_create`, Волна спрашивает с планом «<что сделаю>. Сделать?».
2. После «да» `techcard_create` (`skills/create.ts`) ставит задание. В нём правила Волны поверх skill-creator: папка `data/skills/<name>`, нейтральное описание «когда…» для Jev, `allowed-tools` только из инструментов этого ядра, `metadata.tier` решает агент, вопросы владельцу — через инструмент вопросов агента, коротко и как своё мнение («Мне кажется, раз в неделю. Так?»), без просмотрщика skill-creator.
3. Агент пишет пробные фразы `evals/volna-routing.json` (`should` и `shouldNot`, по 8) и запускает `npm run skills -- check <name>` (`skills/check.ts`): каждая фраза идёт к Jev среди всех техкарт. Нужно не меньше 85% в обеих группах. Не прошла за три правки описания — `metadata.route: "off"`, техкарта остаётся текстом.
4. Итог приходит, как у любой работы. Короткую правку правил владельца Волна по-прежнему делает сама через `techcard_write`.

Скилл skill-creator форкать не нужно: если понадобятся ещё правила, они дописываются в задание или слоем «Правил владельца».

## 9. Дальше

- При делегировании в агента можно передавать путь к папке скилла, а не пересказ. Формат у Claude родной.
- Экран «Память» пока не показывает источник, уровень и плагин техкарты: решается через макет на одобрение.
