# Протокол тестирования Волны

Как проверять все функции Волны: порядок, подготовка, сценарии с ожидаемым результатом и где смотреть доказательства. Составлен 26.09.2026. Устройство функций описано в [architecture.md](architecture.md) и [core.md](core.md), открытые проверки перечислены в [pending.md](pending.md), прежняя матрица результатов лежит в [device-checklist.md](device-checklist.md). Если появилась новая функция, в том же изменении сюда добавляется строка с новым номером. Номера не переиспользуются.

## 1. Правила

- **Где проверено.** Результат пишется с указанием среды: `тесты`, `сим` (симулятор), `Mac` (ядро без звонка), `iPhone` (живой звонок). По `тесты` или `сим` пункт с `iPhone` не закрывается ([AGENTS.md](../AGENTS.md)).
- **Доказательство.** Для каждого пункта нужно указать, где подтверждение: строку лога ядра, событие в консоли (`127.0.0.1:25452`, вкладка «История»), путь в `npm run metrics`, журнал Пульта (`~/Library/Logs/VolnaPult.log`) или системное приложение на iPhone. Если пункт закрыт только на слух, пометить «на слух».
- **Статусы:** `прошло`, `не прошло`, `частично`, `не проверено`. При «не прошло» записать, что было на самом деле, и время звонка, чтобы найти его в консоли и замерах.
- **Тестовые данные.** Всё, что Волна создаёт в прогоне, содержит слово «тест»: «напомни завтра в девять тест полить цветы». Так уборка сводится к поиску по слову. Реальные письма, платежи и удаление настоящих данных не проверяются никогда. Запреты проверяются только тем, что Волна отказывается.
- **Один сценарий на реплику.** Не смешивать проверки в одной фразе, иначе в консоли не понять, какой маршрут что выбрал.

## 2. Виды прогона

| Прогон | Когда | Что входит | Время |
|---|---|---|---|
| Автоматический | После любого изменения кода | Раздел 4 | ~5 мин |
| Дымовой | После перезапуска ядра, новой сборки на iPhone, смены моделей в `.env` | Пункты с пометкой ★ | ~15 мин, 3 звонка |
| По изменению | После правки конкретной области | Группы из таблицы раздела 15 плюс дымовой | по объёму |
| Полный | Перед тем как считать функцию проверенной на iPhone; раз в неделю, пока идёт активная разработка | Все разделы | 2–3 ч, лучше в два захода |

## 3. Подготовка

### 3.1 Mac

1. Код ядра и Пульта совпадает с тем, что проверяется: `git log -1` записать в журнал прогона.
2. Перезапустить ядро на этом коде ([device-setup.md](device-setup.md#повторный-запуск-ядра-после-перезагрузки-mac)). В логе старта должны быть строки `Delegation:` и `Tasks:`, при `HELM_TOKEN` строка `helm.ready`, при включённых плагинах нет `plugin.mcp_failed`.
3. Пересобрать и запустить Пульт, если менялся `archive/pult/`: `archive/pult/scripts/build-pult-app.sh --run`. В настройках Пульта группа «Волна» включена, «Универсальный доступ» выдан.
4. Открыть консоль ядра `http://127.0.0.1:25452`, режим «Авто».
5. Записать модели из `.env`: `CLIENT_MODEL_SIMPLE`, `CLIENT_MODEL_STANDARD`, `CLIENT_SEARCH_MODEL`, `MEMORY_MODEL`, `JEV_MODE`, `HELM_INSTANCE` и `HELM_MODEL`.
6. Сделать копию `core/data/`: `cp -R core/data /tmp/volna-data-<дата>`. Прогон меняет память, техкарты и задания, копия позволяет вернуть их.

### 3.2 iPhone

1. Сборка из того же коммита. В «Настройки → Режим отладки» указан адрес ядра, «Проверить» даёт успех.
2. В «Разрешениях» выданы микрофон, Siri, напоминания, календарь и контакты. Для пунктов об отказе в доступе разрешения снимаются в настройках iOS отдельно.
3. Тестовые контакты: «Маша Тест-один» и «Маша Тест-два» с разными номерами, «Дима Тест» с одним номером.
4. Уровень близости «Замечает сама», если в пункте не сказано иное.
5. Записать модель iPhone, версию iOS, язык Siri и способ подключения (Wi-Fi `.local`, IP или ngrok).

### 3.3 Журнал прогона

Результат пишется в `docs/test-runs/<ГГГГ-ММ-ДД>.md`:

```md
# Прогон <дата>, <вид прогона>
Коммит: …  Ядро перезапущено: …  Пульт собран: …
iPhone: …, iOS …, Siri: …, связь: …
Модели: simple …, standard …, search …, memory …, Jev …, «Штурвал» …

| № | Среда | Статус | Доказательство / что было |
|---|---|---|---|
| З-01 | iPhone | прошло | консоль 14:02, greeting phrase, 2,1 с |
```

Итоги полного прогона переносятся в [pending.md](pending.md): проверенное вычёркивается, найденные сбои дописываются.
