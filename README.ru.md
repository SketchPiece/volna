# Волна — iPhone prototype

[English](README.md) · **Русский**

Нативное iOS-приложение для быстрого голосового разговора с AI. SwiftUI + CallKit + SiriKit/App Intents + OpenAI Realtime через WebRTC. Минимальная iOS: 18.0.

## Структура

| Папка | Что там |
|---|---|
| `ios/` | iOS-приложение: `CallAssistant.xcodeproj`, код, Siri-расширение, тесты, скрипты проекта |
| `core/` | Ядро на Node: держит ключи, поднимает GPT-Live, исполняет инструменты, память и задания ([docs/core.md](docs/core.md)) |
| `docs/` | Архитектура, дизайн-система, холсты, протоколы проверок |
| `scripts/` | Скрипты уровня репозитория |
| `relay/` | «Узел»: помощник на Mac, через него ядро в облаке работает со «Штурвалом» ([docs/relay.md](docs/relay.md)) |
| `archive/` | Не в работе: Mac-приложение «Пульт» и диагностика Speakerbox |

## Запуск в симуляторе

1. Откройте `ios/CallAssistant.xcodeproj`, выберите схему **CallAssistant** и iPhone Simulator.
2. В `core` скопируйте `.env.example` в `.env`, добавьте свой `OPENAI_API_KEY`. Не коммитьте `.env`.
3. Запустите ядро (Node.js 22.18+):

   ```sh
   cd core
   npm start
   ```

4. Запустите приложение в Xcode. В настройках включите **Режим отладки** (группа «Ядро» видна только в нём): по умолчанию стоит облачное ядро `https://your-core.example.com`, для локального укажите `http://127.0.0.1:8787` → **Проверить**.
5. Разрешите микрофон и нажмите **Позвонить Волне**. Может понадобиться разрешение микрофона для Simulator в macOS.
6. Что происходит с моделью во время звонка, видно в консоли ядра: http://127.0.0.1:25452 (только на этом Mac, [core.md, 4k](docs/core.md#4k-консоль-ядра)).

Ключ хранится только на Mac. Ядро создаёт GPT-Live-сессию и обменивает SDP с OpenAI; звук передаётся напрямую по WebRTC. С 22.09.2026 голосовая модель `gpt-live-1` (`OPENAI_LIVE_MODEL`): полный дуплекс, без детектора речи, перебивание только голосом, кнопки «Перебить» нет. Инструменты, поиск и память исполняет само ядро: на делегирование Live отвечают модели `CLIENT_MODEL_SIMPLE` (OpenRouter) и `CLIENT_MODEL_STANDARD` (модели `openai/*` напрямую через Responses API тем же `OPENAI_API_KEY`), поэтому `OPEN_ROUTER_API_KEY` в `core/.env` обязателен. Голос выбирается в **Настройки → Голос Волны → Голос**: Meridian (по умолчанию), Stone, Vesper, Ripple, Beacon, Cinder, Gleam, Willow, Quartz, Delta, Bossa, Tempo. Выбор сохраняется сразу и применяется к следующему звонку, включая запуск через Siri. Русское произношение голосов Live OpenAI не документирует, проверяется на телефоне.

Без ключа доступен **Настройки → Открыть демо звонка**: только интерфейс, без микрофона и сетевых запросов. Кнопка настоящего звонка при отсутствии ключа сообщает об ошибке, а не имитирует AI.

## Что реализовано

- Один тап → подключение → несколько реплик в общей сессии.
- Semantic VAD и автоматическое прерывание ответа, когда пользователь начинает говорить.
- Mute и стенограмма звонка (история реплик обеих сторон, только в памяти до следующего звонка). Кнопок динамика и выбора аудиовхода нет.
- По умолчанию — громкая связь на встроенном динамике; датчик приближения переключает звук на разговорный динамик у уха и обратно при отдалении. Подключённые внешние аудиоустройства сохраняют приоритет. Датчик у уха всегда запрещает громкую связь. После завершения мониторинг датчика отключается. Проверка физического переключения на iPhone требуется отдельно от сборки.
- CallKit на устройстве: системный звонок, управление аудиосессией, завершение, mute.
- SiriKit extension для `INStartCallIntent`, единый встроенный AI-адресат и системная передача в CallKit.
- Тайм-аут подключения, обработка потери связи, отмена незавершённого подключения.
- При завершении отключаются локальный аудиотрек, WebRTC-аудио, data channel и peer connection. Отменяются сетевой запрос и таймер.
- Локальный экран настроек и время подключения. Текст текущего ответа хранится только в памяти.
- Инструменты Волны: время, память, встроенный поиск в интернете бэкенд-модели и инструменты телефона: напоминания, календарь, контакты в системных приложениях через EventKit и Contacts. Доступ включается в **Настройки → Разрешения**; без доступа инструмент не объявляется модели. Дизайн: [docs/design/volna-tools.html](docs/design/volna-tools.html). Проверено тестами и сборкой в симуляторе, на iPhone не проверено.

## Дизайн

Интерфейс собран по дизайн-системе «Бакелит и лампа» (ВОЛНА-1): светлый неоморфный корпус слоновой кости, один сигнальный красный, янтарные лампы состояний, тёмное стекло только для текста ответа. Спецификация с токенами, компонентами, состояниями и экранами: [docs/design/volna-design-system.html](docs/design/volna-design-system.html). Тема следует системной настройке: светлый корпус или «чёрный бакелит».

В центре экрана звонка знак-волна (`WaveMark`): в покое совпадает с логотипом, при соединении бежит мелкой рябью, при приёме дышит, когда Волна говорит, растёт по амплитуде и бежит, а кольцо вокруг загорается. Амплитуда берётся из статистики WebRTC на настоящем звонке; в демо и симуляторе используется синтетическая огибающая. Тёмная тема «чёрный бакелит» включается по системной настройке. Reduce Motion останавливает анимацию.

- Токены и тени: `ios/CallAssistant/UI/Theme/WaveTheme.swift`.
- Компоненты: `ios/CallAssistant/UI/Components/` (знак, лампы, статус-пилюля, кнопки, строки, карточки, группы настроек).
- Шрифты Unbounded, IBM Plex Sans, IBM Plex Mono лежат в `ios/CallAssistant/Resources/Fonts` под лицензией SIL OFL 1.1 и объявлены в `UIAppFonts`.
- Иконка приложения: `ios/CallAssistant/Resources/Assets.xcassets/AppIcon.appiconset` (одна картинка 1024×1024, красный диск с волной на корпусе).
- Новые файлы, шрифты и каталог ресурсов добавлены в проект скриптом `ios/scripts/add-design-resources.rb`; `ios/scripts/generate-project.rb` обновлён и включает их при полной регенерации.

## Siri и заблокированный экран — гипотеза, а не подтверждённая функция

В контрольной Zorava подтверждён запуск SiriKit → CallKit → тестовый звук без разблокировки. Этот путь перенесён в Волну; обычный Realtime-разговор работает, но запуск с блокировки пока не подтверждён. Последний журнал показал, что Siri выбирала старое foreground-действие `CallGPTIntent` через `BackgroundShortcutRunner`. Оно удалено из текущей сборки, оставлен системный SiriKit-звонок. [Ход диагностики](docs/siri-investigation.md).

Apple указывает, что `INStartCallIntent` не всегда требует разблокированный телефон. Это основание для проверки, но не гарантия для конкретного устройства, состояния процесса и настроек Siri.

На реальном iPhone:

1. В Xcode выберите свою Signing Team для приложения и SiriExtension, при необходимости замените bundle ID. Siri entitlement требует поддерживающего provisioning profile.
2. Установите приложение; один раз откройте его, настройте HTTPS-адрес ядра, разрешите микрофон и Siri. Включите Siri при блокировке в настройках iOS.
3. Откройте приложение для регистрации словаря AI-адресата. Скажите голосом через Siri, вызванную боковой кнопкой: **«Позвони Волне через Волну»** / **«Call Volna using Volna»**. Подсказка выбирается по языку Siri.
4. Если в «Командах» сохранён старый «Call Volna» / «Позвони Волне», переименуйте его, чтобы Siri не выбирала его вместо системного звонка. Старое App Intent-действие больше не поддерживается.
5. Выполните матрицу [проверок на устройстве](docs/device-checklist.md).

В Simulator CallKit заменён прямой активацией аудиосессии. Он позволяет проверить экран и подключение Realtime, но **не подтверждает** запуск с блокировки, Bluetooth/AirPods, системные прерывания и поведение после выгрузки приложения.

## Ядро для iPhone

Пошаговая настройка установленного прототипа и повторный запуск ядра: [device-setup.md](docs/device-setup.md).

`127.0.0.1` на iPhone указывает на сам телефон. Для устройства нужен доступный **HTTPS** URL ядра. Укажите его в настройках приложения и задайте одинаковый `BRIDGE_TOKEN` в ядре и в приложении. Токен приложения хранится в Keychain с доступностью после первой разблокировки устройства.

Ядро по умолчанию слушает только localhost. Для внешнего интерфейса требует `BRIDGE_TOKEN`; TLS должен завершаться на HTTPS reverse proxy. Встроены ограничение размера SDP, лимит попыток, тайм-аут и отказ запросам из браузеров. Это однопользовательский прототип, не публичный сервис: перед выпуском нужны пользовательская аутентификация, квоты и управление секретами.

Новые ключи и пополнение API-баланса не выполняются автоматически. Подписка ChatGPT не является проверкой API-баланса. `/health` проверяет только наличие настройки ключа, доступ к модели проверяется при настоящем звонке.

## Проверки

```sh
cd core
npm test
```

```sh
cd ios && xcodebuild -project CallAssistant.xcodeproj -scheme CallAssistant \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath build test
```

Unit-тесты хостятся приложением, поэтому вся команда запускается с подписью для симулятора («Sign to Run Locally»): с `CODE_SIGNING_ALLOWED=NO` у процесса нет Siri-entitlement, и `INPreferences.siriLanguageCode()` при старте приложения завершает его. Отдельный тест `DesignScreenshots` снимает экраны (покой, настройки, голос, память с демонстрационными данными по флагу `--memory-preview`, демо-звонок, mute, текст ответа, конец связи) во вложения `.xcresult` для сверки с дизайн-документом; запуск только его: `-only-testing:CallAssistantUITests/DesignScreenshots`.

Тесты ядра проверяют авторизацию, отказ браузерным запросам, проверку SDP, ограничения частоты и размера, конфигурацию VAD, выбор голоса, ошибки upstream, объявление инструментов и их выполнение через sideband, а также память: хранилище, секцию инструкций по уровням близости, запись и извлечение транскрипта, инструменты `remember/forget/recall`, REST `/memory`. Устройство ядра и добавление инструментов: [docs/core.md](docs/core.md). UI-тесты проверяют цикл демо → mute → завершение, запрет небезопасного внешнего HTTP-адреса, сохранение выбранного голоса после перезапуска и снимают экраны для сверки с дизайном.

Для повторного создания проекта: `ruby ios/scripts/generate-project.rb` (gem `xcodeproj`). Готовый `.xcodeproj` уже включён; генератор для обычного запуска не нужен. WebRTC привязан к SPM-версии 153.0.0.

## Характер Волны и локализация Siri

Волна отвечает в манере советского ретрофутуристического научного помощника: спокойная уверенность, лёгкая ирония, редкое «товарищ», короткие содержательные ответы. Язык ответа подстраивается под речь пользователя. Выбранный голос Realtime сохраняется; характер задаётся инструкциями новой сессии.

Примеры системного звонка в `AppIntentVocabulary.plist` и имя приложения локализованы для `ru` и `en`; словарь Siri содержит Volna и Волна. Отдельная проверка обоих языков и запуска Realtime-разговора с блокировки ещё требуется.

Источники: [язык Siri](https://developer.apple.com/documentation/intents/inpreferences), [варианты имени приложения](https://developer.apple.com/documentation/sirikit/specifying-synonyms-for-your-app-name).
